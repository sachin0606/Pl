API v1.0 / FIX44 Target Contract
17 September 2026

Document status and implementation boundary

Purpose. This is the normative integration contract for the FIX44 platform target. Every operation described here is intended to map to a real Kashtrix service/command handler, not to a decorative UI label.
Acceptance boundary. An endpoint or protocol is only production-ready after the Windows build and its corresponding hardware/network interoperability test has passed. ST 2110/PTP/NMOS/2022-7, DeckLink ANC, Dolby and multi-node HA require target infrastructure validation.

All transports feed one validated internal command/event bus. A TAKE over REST, WebSocket or TCP must execute the same authorization, validation, audit and playout handler. UDP is intentionally restricted for safety-sensitive commands unless acknowledgement/retry policy is explicitly enabled.

5. Persistent TCP JSONL API

UTF-8 newline-delimited JSON. Each complete JSON object ends in LF. Authentication must complete before commands or subscriptions.

{"type":"auth","apiKey":"YOUR_KEY","client":"automation-1"}
{"type":"subscribe","topics":["playout.KTX-PLAYOUT-01.*","alarm.*"]}
{"v":"1.0","id":"tcp-1","type":"command","module":"playout","channelId":"KTX-PLAYOUT-01","action":"next","params":{}}

Required behaviors: PING/PONG heartbeat, idle timeout, message-size limit, malformed-frame rejection, correlation IDs, reconnect-safe idempotency and explicit server error records.

16. MCP - Model Context Protocol integration

Specification target: MCP 2026-07-28. The remote Kashtrix MCP endpoint uses Streamable HTTP. The current specification moved to a stateless protocol core, requires HTTP routing headers such as Mcp-Method and Mcp-Name, and moved asynchronous Tasks into the io.modelcontextprotocol/tasks extension. Legacy HTTP+SSE is not the target for new Kashtrix deployments.

Endpoint: POST /mcp over HTTPS. MCP does not bypass broadcast safety. Each tool maps to the same Kashtrix service and permission checks used by REST/TCP/WebSocket.

Appendix C. API acceptance checklist

  • REST/WebSocket/TCP commands invoke the same validated service handler.
  • Channel Controller multi-target command returns per-channel result, not one fake global success.
  • CG Controller Preview and Program remain independent and multi-channel targeting is verified.
  • TCP heartbeat, reconnect, malformed JSON and oversized message handling are tested.
  • WebSocket reconnect/resubscribe and event sequence gaps are tested.
  • UDP loss/duplicate/reorder behavior is tested; critical commands do not depend on unacknowledged UDP.
  • API key/JWT/OIDC mapping to RBAC is tested.
  • Idempotency prevents duplicate TAKE/archive/schedule commands.
  • MCP tools cannot bypass roles, output interlocks or hardware readiness.
  • MCP long operations return real task state and final result/error.
  • Audit contains transport, identity, request ID, module, target and outcome.
